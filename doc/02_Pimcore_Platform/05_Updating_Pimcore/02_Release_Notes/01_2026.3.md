# Release 2026.3

Here you will find the important new features and release notes of the Platform Version 2026.3 release.
Please also make sure to run all migrations after update as always.

## New Key Features

### Generic Data Index: Performance, Stability & Traceability

The Generic Data Index bundle powers search, grids, and listings across the Pimcore Platform. This release brings a
coordinated set of improvements in three areas: faster indexing on large installations, an index that stays correct
and intact under real-world conditions, and full operational visibility into what the index is doing and why.

- **Performance** — indexing now does significantly less work per element: tags are fetched once, localized fields
  no longer normalize the full dataset just to read keys, and inheritance resolution is cached for elements sharing
  the same parent chain. A new opt-in `calculated_fields_index_mode: query_store` indexes saved calculated-field
  values instead of executing calculators during every reindex, while values remain searchable, filterable, and
  sortable.
- **Stability** — transient cluster failures during native reindexing no longer trigger recreation of the live
  index; class mapping checksums are now stable across array key order, so configuration-only changes (like
  reordered languages) no longer trigger unnecessary full reindexes; moving or renaming elements now reliably
  updates descendant paths in the search index across all element types.
- **Traceability** — a dedicated log channel, structured exception context, and dispatch IDs make queue batches
  traceable end to end. The new read-only `generic-data-index:status` command shows queue depth, index document
  counts and sizes, and interrupted reindexes.
- **Index export/import**: new `generic-data-index:snapshot:export`/`:import` commands move a full search index
  between installations in minutes instead of a multi-hour reindex
  ([details](https://github.com/pimcore/generic-data-index-bundle/pull/513)).

Also added: a `SearchBodyProcessorInterface` extension point, a `generic-data-index:cleanup:unused-indices` command,
and relevance scores on search result items.

### Pimcore Portal Rework

The customer portal frontend is being rebuilt on the shared foundation with Studio, introducing a Module Federation
plugin/extension system: the portal exposes a stable SDK, and separate plugin packages add custom UI at defined
extension points ("slots"), switchable per portal. Pages stay server-rendered for good URLs and performance — the
real change is the extension model, which lets partners and projects add custom features as plugins without forking
the core, and lets the core keep evolving without breaking existing partner implementations.

This work introduces **`pimcore/portal-ui-kit`**
([docs](https://github.com/pimcore/portal-ui-kit/blob/2026.3/docs/README.md)), a new reusable frontend foundation
shared with the Studio UI (the application host, dependency injection, the SDK, and the plugin/slot extension
model), intended to become the base for future portal-like applications. See
[Portal Frontend Plugins](https://github.com/pimcore/portal-engine/blob/2026.3/doc/15_Development_Documentation/15_Customize_and_Extend_Behavior/16_Portal_Frontend_Plugins.md)
for how to build one.

As part of this release, the Studio-stack frontend also gains **Direct Edit** support through the Direct Edit
bundle's Studio session model.

The legacy (non-Studio-stack) Portal frontend is deprecated and will be removed in 2027.1. New portals now default
to the Studio-stack frontend; existing portals keep their current frontend variant unless changed by hand.

### Pimcore Embeddings (Experimental)

An experimental embeddings-based feature (part of the Enterprise `backend-power-tools-bundle`) combining semantic
search and similarity detection for data objects, assets, and document/text assets has landed, off by default.
Embeddings are generated by an inference service you bring — a managed embeddings API or a self-hosted
OpenAI-compatible server — and the provider interface is public, so a custom provider can be implemented today for
endpoints the shipped one doesn't cover.

This opens the door to semantic image search (searching by describing an image's content in natural language),
image duplicate detection, and object duplicate detection. Semantic search sits behind a dedicated
`bptb_semantic_search_permission` permission. Enabling the feature adds a new table, so run the migration command
after updating. See
[Embeddings documentation](https://github.com/pimcore/backend-power-tools-bundle/blob/2026.3/doc/40_Embeddings/README.md)
for setup and configuration.

### OAuth 2.1 Authorization Server (Studio Backend)

Studio Backend Bundle now ships an embedded, opt-in OAuth 2.1 authorization and resource server — disabled by
default and isolated from the application's own security configuration. It supports the `authorization_code` grant
with PKCE, a Studio UI consent screen, refresh tokens, and standard discovery (RFC 8414/9728). Issued tokens are
accepted on the MCP endpoint, and Datahub Simple REST now accepts OAuth access tokens on its own REST and MCP
endpoints too.

### Deprecation of Quill Bundle

The Quill Bundle (WYSIWYG editor based on [Quill 2.x](https://quilljs.com/)) is deprecated starting with this
release and marked `abandoned` in Composer (which will warn on install/update). Existing installations are not
affected before then, but new projects should use the replacement,
[Pimcore WYSIWYG Editor](https://github.com/pimcore/pimcore-wysiwyg-editor) (`pimcore/pimcore-wysiwyg-editor`),
instead.

## General

- **Elasticsearch requirement raised**: the minimum supported Elasticsearch server version across the platform is
  now `8.12.2` (via `pimcore/elasticsearch-client` `^2026.3`).
- **Notification preferences**: users can now choose, per notification type, whether to be notified and through
  which channel (in-app pop-up, email); bundles can contribute new notification types and delivery channels.
- **New languages**: Dutch and Polish translations added across Studio and roughly 25 bundles.
- **Extension of Pimcore Telemetry**: telemetry capabilities have been extended to gain better insights into how the
  platform is used in real-world environments, helping identify areas for improvement and prioritize the roadmap.
  Data privacy remains a key priority — telemetry is designed to collect only the information required for product
  improvement, with a strong focus on data minimization and transparency.

## Additional Changes

### Core Framework

- Class definition files are now cached in-process, so clearing the runtime cache in long-running scripts no longer
  re-includes the definition file on every `ClassDefinition::getById()` call.
- The legacy admin controllers of the bundled `ApplicationLogger`, `CustomReports`, and `SEO` bundles have been
  **removed**, along with their `/admin/bundle/*` routes — their functionality is available through the Studio
  backend API.
- **Security fix**: `Asset::correctPath()` now also renames an asset filename ending in `.html`, `.htm`, `.xhtml`,
  `.xht`, `.shtml`, `.js`, or `.mjs` (appending `.txt`) whenever that filename is newly set or changed, mitigating a
  stored-XSS vector (GHSA-4xrp-5ggg-fg5p). Existing assets under these extensions are unaffected unless renamed.
- Custom renderlet configuration parameters are now passed as query parameters instead of request attributes;
  accessing them via `$request->attributes->get()` is deprecated and will be removed in Pimcore 2027 — update to
  `$request->query->get()`.
- Saving a data object with many languages enabled is now significantly faster: primary-key lookups for
  localized/query tables are no longer repeated per language on every save.
- Less thumbnail I/O, and thumbnail cache lifetime is now configurable.
- MIME types can now be overridden per file extension.
- A custom HTML sanitizer is now available.
- Calculated Value calculators can now receive arguments.
- Workflows support `custom_extensions`.
- New `NoteEvents::POST_DELETE` event.

### Datahub

- Added GraphQL query support for the `Renderlet` document editable — a purely additive schema change.

### Datahub Simple REST

- Asset delivery is now limited to the endpoint's configured variants — requests that previously returned `200` may
  now return `404` or a refusal if an integration relied on delivering an asset/thumbnail outside those settings.
- Mapping reindex now runs as an asynchronous task instead of blocking on a synchronous rebuild, so it no longer
  times out on managed clusters behind a proxy.
- The MCP server is no longer marked experimental, following a series of quality and reliability improvements.

### Data Importer

- A `PreSaveEvent` listener can now skip persisting the current element (`setSkipSave(true)`); imports without such
  a listener are unaffected.

### Direct Edit

- Deprecated: the bundle's own Mercure hub and modal protocol, which only served the classic admin UI and the
  legacy Portal Engine frontend — will be removed in 2027.1.

### Generic Data Index

- See "New Key Features" above for the full performance/stability/traceability overview.

### Portal Engine

- Direct Edit is now available on the Studio-stack frontend.
- **Symfony 8.0 BC break**: `Voter::voteOnAttribute()` gains a `$vote` argument — custom voters overriding this
  method must add the parameter or PHP raises a fatal error.

### Studio Backend Bundle

- The data object detail response's inheritance metadata now optionally exposes the value a field would inherit
  from its nearest ancestor, in addition to whether it's currently inherited.

### Studio UI

- Accessibility improvements: WCAG AA color contrast, visible focus states, a skip link, and focus restored after
  closing a dialog.
- Modals can now be dragged to reveal hidden content, and the sidebar is resizable and can be pinned open.
- Batch editing now supports multiple languages at once.
- Grid page sizes are now configurable.
- Version view now shows co-authors and a Properties section.
- New user owner/modification columns and filters, plus an asset size filter, in grids.
- Inline upload in the relation editable, and creating an object directly from the relation toolbar.

### Backend Power Tools

- Added Embeddings (experimental) support — see "New Key Features" above.

### Symfony 8 Readiness

- Roughly 20 bundles have been updated for compatibility with the upcoming Symfony 8 release.
