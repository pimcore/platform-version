# Release 2026.3

Here you will find the important new features and release notes of the Platform Version 2026.3 release.
Please also make sure to run all migrations after update as always.

## Most Important New Features

### Generic Data Index: Performance, Stability & Traceability

The Generic Data Index bundle powers search, grids, and listings across the Pimcore Platform. This release brings a
coordinated set of improvements in three areas: faster indexing on large installations, an index that stays correct
and intact under real-world conditions, and full operational visibility into what the index is doing and why.

- **Performance** — indexing now does significantly less work per element: tags are fetched once, localized fields
  no longer normalize the full dataset just to read keys, and inheritance resolution is cached for elements sharing
  the same parent chain. A new opt-in `calculated_fields_index_mode: query_store` indexes saved calculated-field
  values instead of executing calculators during every reindex, while values remain searchable, filterable, and
  sortable.
- **Stability** — transient cluster failures during native reindexing no longer trigger recreation of the live
  index; class mapping checksums are now stable across array key order, so configuration-only changes (like
  reordered languages) no longer trigger unnecessary full reindexes; moving or renaming elements now reliably
  updates descendant paths in the search index across all element types.
- **Traceability** — a dedicated log channel, structured exception context, and dispatch IDs make queue batches
  traceable end to end. The new read-only `generic-data-index:status` command shows queue depth, index document
  counts and sizes, and interrupted reindexes.

Also added: a `SearchBodyProcessorInterface` extension point, a `generic-data-index:cleanup:unused-indices` command,
and relevance scores on search result items. The minimum supported Elasticsearch server version is now `8.12.2`.

### Pimcore Portal Rework

The customer portal frontend is being rebuilt on the shared foundation with Studio, introducing a Module Federation
plugin/extension system: the portal exposes a stable SDK, and separate plugin packages add custom UI at defined
extension points ("slots"), switchable per portal. Pages stay server-rendered for good URLs and performance — the
real change is the extension model, which lets partners and projects add custom features as plugins without forking
the core, and lets the core keep evolving without breaking existing partner implementations.

This work introduces **`pimcore/portal-ui-kit`**, a new reusable frontend foundation shared with the Studio UI (the
application host, dependency injection, the SDK, and the plugin/slot extension model), intended to become the base
for future portal-like applications.

As part of this release, the Studio-stack frontend also gains **Direct Edit** support through the Direct Edit
bundle's Studio session model.

### Pimcore Embeddings (Experimental)

An experimental embeddings-based feature combining semantic search and similarity detection for assets and data
objects has landed, off by default. The goal is a reusable service for generating embeddings from images and
textual metadata, storing those vectors in a search-optimized backend for efficient querying, with an
adapter-based architecture to keep the embedding provider flexible (Pimcore's own inference service as well as
third-party services in the future).

This opens the door to semantic image search (searching by describing an image's content in natural language),
image duplicate detection, and object duplicate detection. As an experimental feature, it is best suited for
validation and feedback before broader rollout — enabling it adds a new table, so run the migration command after
updating.

### Deprecation of Quill Bundle

The Quill Bundle (WYSIWYG editor based on [Quill 2.x](https://quilljs.com/)) is deprecated starting with this
release. It remains fully supported in the 2026.x LTS, but will no longer be part of the Pimcore Platform LTS
starting with the 2027 release line. Existing installations are not affected before then.

## General

- **Extension of Pimcore Telemetry**: telemetry capabilities have been extended to gain better insights into how the
  platform is used in real-world environments, helping identify areas for improvement and prioritize the roadmap.
  Data privacy remains a key priority — telemetry is designed to collect only the information required for product
  improvement, with a strong focus on data minimization and transparency. As part of this, the Copilot Agent Bundle
  now reports a daily boolean (whether at least one automation or interaction action is configured) and per-state
  automation job-run counts from the last 24 hours; action names are never emitted.
- **Further pre-release of Agent Bundle (Beta)**: the Pimcore Copilot Agent Bundle adds support for headless Agent
  Tasks, letting Pimcore Copilot as well as external tools and integrations delegate work to the Pimcore Agent and
  retrieve the resulting output — a foundation for using the Agent beyond the Studio user interface. The release
  also integrates the Agent with the Pimcore Workflow Engine, enabling agent capabilities to become part of existing
  business processes, plus configuration improvements, UI enhancements, and bug fixes.

## Additional Changes

### Core Framework

- Class definition files are now cached in-process, so clearing the runtime cache in long-running scripts no longer
  re-includes the definition file on every `ClassDefinition::getById()` call.
- The legacy admin controllers of the bundled `ApplicationLogger`, `CustomReports`, and `SEO` bundles have been
  **removed**, along with their `/admin/bundle/*` routes — their functionality is available through the Studio
  backend API.

### Data Hub

- Added GraphQL query support for the `Renderlet` document editable — a purely additive schema change.

### Data Hub Simple REST

- Minimum Elasticsearch version raised to `8.12.2`.
- Asset delivery is now limited to the endpoint's configured variants — requests that previously returned `200` may
  now return `404` or a refusal if an integration relied on delivering an asset/thumbnail outside those settings.
- Mapping reindex now runs as an asynchronous task instead of blocking on a synchronous rebuild, so it no longer
  times out on managed clusters behind a proxy.

### Data Importer

- A `PreSaveEvent` listener can now skip persisting the current element (`setSkipSave(true)`); imports without such
  a listener are unaffected.

### Direct Edit

- Deprecated: the bundle's own Mercure hub and modal protocol, which only served the classic admin UI and the
  legacy Portal Engine frontend — will be removed in 2027.1.

### Generic Data Index

- See "Most Important New Features" above for the full performance/stability/traceability overview.

### Portal Engine

- Direct Edit is now available on the Studio-stack frontend.
- **Symfony 8.0 BC break**: `Voter::voteOnAttribute()` gains a `$vote` argument — custom voters overriding this
  method must add the parameter or PHP raises a fatal error.

### Studio Backend Bundle

- The data object detail response's inheritance metadata now optionally exposes the value a field would inherit
  from its nearest ancestor, in addition to whether it's currently inherited.

### Backend Power Tools

- Added Embeddings (experimental) support — see "Most Important New Features" above.

### Copilot Bundle

- Raised minimum `pimcore/studio-backend-bundle` requirement to `^2026.3` and minimum `pimcore/pimcore` requirement
  to `^2026.3`.
